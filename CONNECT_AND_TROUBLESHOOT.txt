STATE ISSUE — CONNECTIVITY QUICK GUIDE
=======================================

CONNECTION ADDRESSES
--------------------
Host computer: run START_STATE_ISSUE.bat. It opens:
    http://127.0.0.1:8787/

Workstation: connect to the host's approved private network, then run
OPEN_STATE_ISSUE.bat. The host URL is configured in that file. You can also
enter http://10.9.50.171:8787/ directly in the browser.

The host and workstation must be able to reach each other over the approved
private network. The server listens on TCP port 8787. The current host address
is 10.9.50.171. Opening Stateissue.html directly from a folder does not connect
to shared data.

INTERNET VS. LOCAL CONNECTIVITY
-------------------------------
After installation, normal app use does not require internet access. Host and
workstations do need their local network/VPN path to the server. Internet is
needed for online setup downloads, first-time pywin32 installation, and the
GitHub update utility. A loss of internet alone does not stop local-network use.

If the host's private-network address changes, update OPEN_STATE_ISSUE.bat on
each workstation. Run SETUP_NEW_COMPUTER.bat on the host as administrator, then
test the new URL.

TROUBLESHOOTING
---------------
1. Host browser cannot connect
   - Check "State Issue Server" in Windows Services (services.msc).
   - Start the service if it is stopped.
   - On the host, open http://127.0.0.1:8787/ directly.
   - If that fails, check the Windows Application event log and the program
     installation. Do not delete or move the database.

2. Host works, workstation cannot connect
   - Confirm both computers are on the intended network/VPN.
   - Check the host URL in OPEN_STATE_ISSUE.bat; test that same URL directly.
   - On the host, run SETUP_NEW_COMPUTER.bat as administrator and check the
     firewall rule for TCP 8787 on the approved private network/VPN.
   - If the direct URL fails too, ask the network administrator to check VPN
     routing and firewall policy. Do not disable the firewall or expose the
     server to the public internet.

3. URL works, shortcut does not
   - Correct the address in OPEN_STATE_ISSUE.bat and use the updated shortcut.

4. Page loads but data will not save
   - Check the page's connection/save status and verify the host service is
     running. Workstations cannot save while disconnected.
   - Host-only offline changes are held in that browser. Keep its browser
     profile and site data intact until it reconnects and syncs.
   - If RECONNECT CONFLICT appears, export/save the local copy, compare it with
     the server data, re-enter needed changes, and discard only after review.

5. Page appears stale
   - Reload, or press Ctrl+F5. Do not clear site data if offline work is pending.
   - Confirm the browser is opening the server URL, not a local HTML file.
