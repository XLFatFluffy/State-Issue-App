STATE ISSUE 2.5.1 ADMIN GUIDE UPDATE
------------------------------------
Set the Display Name separately on each workstation's browser. New requests,
comments, messages, replies, and issuance records use that browser's configured
label so the officer can distinguish work recorded on the worker's workstation.
The previous shared display name is copied to a workstation the first time the
new version is opened there; set the correct name on each workstation after
upgrading. The label is stored in browser storage, not on the server, and is not
verified authentication. It does not provide a secure audit identity.

Inmate profiles can now be flagged HIGH-RISK / NEEDS REVIEW with a required reason.
The flag and its change history are visible on the profile, request screens, and
issuance screens. The flag is a staff review reminder only; it does not approve or
deny requests automatically.

Each request creation or edit now records a snapshot of its request lines, decision,
reason, quantity, status, and configured workstation name. New issuance records include
the workstation name and timestamp. Existing records remain intact, but do
not receive invented history.

Officer and inmate-worker workflows have equivalent access so either can enter,
review, and issue items. There are still no logins or per-user permissions. Display
names are optional attribution labels, not verified identities; anyone with network
access can make changes. Keep the server on a trusted network and do not treat the
program's displayed name as authentication.

Before upgrading, make a backup and retain the database. After updating, test the
high-risk flag, request creation and edit history, issuance from requests, intake
issuance, and issuance from outstanding reminders. Confirm the configured display
name and timestamp appear in issue history.

STATE ISSUE 2.4.5 ADMIN GUIDE UPDATE
The Work Queue is simplified into a shared message board. Staff can send a message,
optionally link a request or inmate, and reply in the conversation. New messages no
longer need a title, category, or priority, and do not need to be resolved or reopened.
Existing messages, replies, and links remain available after the update.

Messages are still assigned IDs and appended atomically by the server, preventing
concurrent posts from different workstations from overwriting one another. Older
server processes are supported through a state-save fallback.

Automatic backups now include inventory catalog-only changes, such as adding or
editing an item before any stock is received. Backup files include collection
counts, and restore checks those counts for missing or truncated data. Existing
backup files remain compatible.

Use SETUP -> Display Name to set the name attached to new entries on this workstation.
Each workstation has a separate setting. The name is optional and is not a login or
verified identity. It is stored with each new entry, so changing the setting does not
change historical attribution. Comments can also be added to inmate profiles,
requests, and individual issuance-history entries.

When upgrading, retain the server database and use the normal backup process before
replacing program files. The application adds the comments collection and display-name
setting automatically when reading existing state. Verify the backup with VERIFY_BACKUP.bat
before relying on it. After upgrading, manually send a message, reply to it, test request
and inmate links, add a comment on each record type, and verify backup/restore using a test copy.
No automated browser test is claimed for these UI workflows.

0. FIRST TIME ON A NEW COMPUTER
-------------------------------
  1. Copy the whole State Issue folder to a permanent folder on the Windows host
     (for example C:\StateIssue). Do not run it from Downloads, a temporary folder,
     or a removable drive.
  2. Double-click SETUP_NEW_COMPUTER.bat. It installs Python if needed, checks the program,
     and configures the firewall for private networks and the host VPN address. Run it as
     administrator so it can apply both firewall rules.
  3. Right-click INSTALL_STATE_ISSUE_SERVICE.bat and choose "Run as administrator".
     The installer installs pywin32, registers the Windows service to start automatically,
     configures Windows to restart it after failures, and starts it. Internet is needed
     for the one-time pywin32 installation.
  4. Double-click START_STATE_ISSUE.bat to open the app on this computer.

1. STARTING AND STOPPING
------------------------
The State Issue Server Windows service runs in the background, including when nobody is
signed in. Closing a command prompt or browser does not stop it. Windows starts it after
reboot and is configured for three automatic restart attempts after a service failure.
Keep the host powered on and prevent it from sleeping during operating hours. Worker
accounts should be standard Windows accounts, not local administrators; an administrator
can still stop or reconfigure the service.

Host computer: double-click START_STATE_ISSUE.bat to open the host's local app at
http://127.0.0.1:8787. Continue using that local address on the host to retain its offline
behavior (see section 1a). If the browser says it cannot connect, have an administrator
check the "State Issue Server" service in Windows Services.

Other computers: double-click OPEN_STATE_ISSUE.bat to connect to the configured host at
http://25.34.230.125:8787. The workstation must be able to reach that host address (for
example, by joining the same VPN/network). The VPN firewall rule permits only connections
to 25.34.230.125 from the 25.0.0.0/8 address range. If the host address changes, update
OPEN_STATE_ISSUE.bat on each workstation and the VPN rule in SETUP_NEW_COMPUTER.bat, then
rerun setup as administrator. You can also open the address directly in a browser and bookmark
it. Keep using START_STATE_ISSUE.bat on the host: its localhost address preserves the host's
offline behavior.
Other computers need nothing installed. Opening Stateissue.html from a folder does NOT work:
the page must be opened from the server address so it can share data.

For planned maintenance, an administrator can stop or start "State Issue Server" in the
Windows Services app (services.msc). Do not stop or disable the service for routine use.
If it is stopped, other computers cannot use the app until it starts again. The app saves
changes automatically; no terminal needs to remain open.

1a. WORKING OFFLINE (host computer only)
-----------------------------------------
Only the host computer — opened at its own address, not the network address — keeps working
if the server program stops or the network drops. Changes made there are saved on that
computer first: the status at the top turns orange and reads "Saved on this computer —
will sync." As soon as the server can be reached again, those changes are sent to it
automatically. Nothing is lost.
Other computers work exactly as before: if they cannot reach the server, they can see the
last data they loaded but cannot save until it is back.
If the status stays orange for a long time, check that the "State Issue Server" service is
running and the network is connected. If it ever turns into a red message reading "RECONNECT
CONFLICT," go to SETUP — it means a change was made somewhere else while this computer
was offline, and the two could not be combined automatically. SETUP explains how to save
and review the stranded changes; nothing is deleted automatically.

2. WHAT THE PROGRAM SAVES
-------------------------
All data is in one file: state_issue_v2.db, in the same folder as the program.
DO NOT DELETE, MOVE OR RENAME it while the server is stopped unless you are restoring a backup.

3. AUTOMATIC BACKUPS
--------------------
The server backs itself up automatically:
  - Daily files: backups\daily_YYYY-MM-DD.db. The last 30 days are kept.
  - Monthly files: backups\monthly_YYYY-MM.db. The last 12 months are kept.
  - Checks happen every hour while the server runs, and when it starts.
  - A backup is only made if the server is running. If it has been off for a day,
    the backup is made the next time it starts.

Each day, copy the newest daily file to a flash drive or another computer. Automatic backups
are on the same computer as the data. A copy elsewhere protects against a failed or stolen computer.

4. VERIFYING A BACKUP (do this regularly - it is quick and changes nothing)
-----------------------------------------------------------------------
Double-click VERIFY_BACKUP.bat, then drag a file from the backups folder onto it
when asked (or just drop the file directly onto the VERIFY_BACKUP.bat icon in
Windows Explorer, which skips the prompt). It opens the backup read-only, checks
it is not damaged, and prints what is in it: the date of the last change saved,
and a count of inmates, items, requests, issues, stock transactions, reminders
and inventory checks. Nothing is changed or restored - it only reads the file.

PASSED means the backup is safe to use if you ever need it.
FAILED means that specific file is damaged - try an older one from the backups
folder, and tell the support person which date failed.

This is the repeatable restore test: run it on your newest daily backup once a
month (for example, the first time you open the program each month) so you know
your backups are actually good before you ever need one. It takes under a minute
and does not touch the live database, so there is no harm in running it often.

5. RESTORING A BACKUP (an actual recovery - not the same as verifying one)
---------------------------------------------------------------------------
Only do this if the data is damaged or lost.
  a. Stop the "State Issue Server" service in Windows Services.
  b. Copy the current state_issue_v2.db somewhere safe, for example into a folder named "damaged".
  c. Copy the backup file you want from the backups folder into the program folder.
  d. Rename the copy to exactly:  state_issue_v2.db
  e. Start the "State Issue Server" service in Windows Services. Check the Setup tab and dashboard.
Check the date on the backup you choose. Anything saved after that date is not in it.
Run VERIFY_BACKUP.bat on the backup file BEFORE step c, so you know it is good
before you commit to using it.

6. RECENT CHANGES (AUDIT LOG)
-----------------------------
SETUP -> Recent Changes shows the last 500 saves: date, time, the configured workstation name of
whoever saved it (set in SETUP -> Display Name on that workstation; shows as — if none was set), the computer
address, and what changed (for example "issues: 2 added"). It does not show inmate or personal
names. The display name is not a login — anyone can change it — so use it as a general guide,
not proof of who made a change. Use it to spot unexpected changes. Records of the log are kept
in the database and are not removed by the program.

The DASHBOARD also has a "Today's Changes" board — the same log, narrowed to just today, so it
is quick to review at a glance. It updates by itself as changes are saved, on any computer, with
no need to reload the page.

7. EXCEL (CSV) EXPORTS
----------------------
SETUP -> Export to Excel: press a button, then open the file in Excel.
REPORTS -> EXPORT REPORT (CSV): exports the report currently on screen.
These files contain personal information. Store them only on the host computer or a secure drive,
and delete copies you no longer need.

8. INVENTORY AND DAILY USE
--------------------------
  - Use the Monthly Inventory Check every month. It is recorded in stock history.
  - Low-stock levels are set in SETUP. The dashboard shows an alert when stock reaches the minimum.

9. IF SOMETHING GOES WRONG
--------------------------
"Could not start" or a service error:
  - Make sure Python 3.8 or newer is installed. Do not change any other files.
  - Open Event Viewer -> Windows Logs -> Application and look for a State Issue Server error.
  - Write down the exact message and send it to the program's support person.
"DATA NOT SAVED" or "CHANGED ON ANOTHER COMPUTER" on screen:
  - Do not keep entering work. Press Refresh or reopen the page so the current copy loads.
  - If the message keeps returning, ask an administrator to check the service in Windows Services.
"DATA NOT LOADED" message:
  - The saved data could not be read. Changes are turned off to protect the data. Contact the
    support person before doing anything else. Do not restore a backup without advice.
  - Once you have advice, run VERIFY_BACKUP.bat on the backup you plan to use (section 4) before
    restoring it, so you restore a good copy the first time.
Nothing appears on other computers: check the address, check that the "State Issue Server"
service is running, and check the network connection on that computer. If the address works
on the host computer but not on others, run SETUP_NEW_COMPUTER.bat as administrator to open
the port and verify that Windows Firewall permits State Issue on the private network.

LIVE UPDATES
  Changes made on one computer appear on the others within about a second. If someone has a
  form open, the update waits until the form is closed. A short message appears when new data arrives.
  If the screen shows "SERVER CONNECTION LOST", that computer cannot reach the host computer.
  Check that the "State Issue Server" service is running. (The host computer itself does
  not show this message — see section 1a, WORKING OFFLINE.)

10. UPDATING THE PROGRAM
-----------------------
  1. Stop the "State Issue Server" service in Windows Services.
  2. Copy the whole program folder to a safe place (this includes the database).
  3. Replace the program files with the new ones. Do not replace or delete state_issue_v2.db.
  4. Start the "State Issue Server" service in Windows Services. The database updates itself when needed.
  5. Check the version in the header and run a test: find an inmate, view a report, export a CSV.
  6. Keep the old copy for at least a month.

11. MESSAGES AND COMMENTS
----------------------------
  - Open Messages. Set your name in SETUP -> Display Name on this workstation if you want it
    attached to messages and replies. It is optional and is not a login — anyone can change it.
  - Type a message, optionally link a request and/or inmate, then press SEND MESSAGE.
  - Reply inside a conversation to keep follow-up communication together. Use search to find
    messages or replies.
  - Messages and replies are shared with everyone who can access the program.
  - Comments can also be added on inmate profiles, requests,
    and individual issuance-history entries (via the COMMENTS button on each issue row). Use
    comments to record updates or context without changing the underlying record.
  - Nothing in Messages or comments can be deleted from the program. Anyone with access
    can read all of it. Keep entries factual and appropriate, and do not use them for anything
    that must be kept private.

12. REQUIREMENTS
----------------
  - Host computer: Windows with Python 3.8 or newer. SETUP_NEW_COMPUTER.bat installs it.
  - Other computers: any Windows computer with a web browser. Nothing else.
  - Other computers need no installation. The host needs internet only for the one-time pywin32
    installation; normal operation does not require internet access.
